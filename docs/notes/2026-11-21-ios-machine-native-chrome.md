## 2026-11-21, iPad and iPhone machines in native chrome (#758)

- A machine's scene on the iPad and iPhone uses the same branches as this device: the app's sidebar, toolbar and notebook screen around the machine's page, loaded with `chrome=native` (`AppModel.page(for:)` asks `Place.drawsNativeChrome(onMac:iosDraws:)`, which doesn't depend on the place).
- `MachineScreen` is deleted. Its job (the page with its own chrome) is the thing this replaces; nothing falls back to it. Only an idiom that is neither iPad nor iPhone, which the app doesn't ship for, would show the page's own chrome, and `content` still passes it the place.
- `IPadSidebar(place:)` takes the Mac's gates: the machine's root and `MachineFileSource(id:server:)` (a progress view until the server listens), `RemoveAction.deleteAlert` (a machine's Delete always asks, the local words stay), `FileSourceError.message` for errors, the offline line, relisting when the machine answers again, `FileChanges.allowed` for `canChange`, and `FolderEntry.canOpen(in:)` so non-page files have no editor.
- Switching place (`ContentView.switchPlace`): saves and closes the iPad's text files, resets the iPhone's path, retires the iPhone's `WebViewStore` for one made for the new place (a coordinator's place is fixed), and calls `PageModel.forgetPage()` before the new page loads. `.id(place)` on the web view and the sidebar makes them new; the iPad's split view and its panel stay, so terminals keep running (the panel is hidden for a machine). `forgetPage` drops the state and queued commands, and `update` ignores state until the app's own load of the new page commits; the iPad's dismantled web view also lets go of the model (`dismantleUIView`), and `WebViewStore.retire()` does so for the iPhone's, without making a web view that was never made.
- Local-only items are off for a machine: the terminal panel, New Terminal and the Running tab's terminals (`allows` on this device's own terminal), Recents and Spotlight (`indexesLocally`), Open Example Notebooks (also the first-launch copy), New DuckDB Console, Open Folder, and the Advanced kernel location menu (`allows(.kernelLocation)`). Search stays: the page searches the machine through its own backend.
- Journals is a tab of the iPad's sidebar for every place (`NavigatorTab.tabs(for:)`, shared with the Mac) and a section of the iPhone's list when there are any. It polls `Journals.fetch` only while it shows (the iPhone's list is on screen); the messages are `Journals.statusMessage`.
- A notebook of this device that a link or Spotlight asks for, or a link's folder switch, switches the scene back to this device first, and a link waiting for the device's page isn't shown while a machine's page is ready.
- Tests: `NavigatorTabTests` (tabs per place), `MachineFileSourceTests` (delete alert words), `PageModelTests` (forgetting the page: state, queued commands, a load under way, a late state), `JournalsTests` (status messages), `PlaceTests` (`drawsNativeChrome` for each place; machine page URL has `chrome=native`).
