## 2026-11-19, Data files open in a data view (#671)

CSV, TSV, JSON and Parquet files open in the page, not the text editor: `DataPane` for the path, chosen by `dataKind` (`src/lib/data-files.ts`) in `App.tsx`, as a notebook is. The Swift sidebars route the same extensions through `page.run("open")` (`FolderEntry.opensInPage`, `PageState.Search.Match.opensInPage`); the two extension lists must match.

Notes:

- The table is `RenderedTable` (table-output.ts) with the filter box outside it, which re-renders the model with the matching rows, so a new filter resets the sort. Types are inferred over the loaded rows: integer, number, boolean, else string. Digit strings with a leading zero or a `+` (zip codes, ids) stay text; integers past 2^53 stay text, which the table's sort compares exactly.
- The CSV parser is ours (about 100 lines, tested) rather than a package: no new dependency. A quote only starts a quoted field at the start of a field, so `5" pipe` is text, as spreadsheets read it.
- The view asks the size first (a contents request without the content) and refuses past a ceiling before fetching: 256 MB for CSV and TSV, 16 MB for JSON and 64 MB for Parquet. Ganymede's `GET /files/<path>` reads the whole file into memory to answer (in the app's own process on iOS), so the client's cap alone doesn't protect a phone. Within the ceiling the page streams the body and cancels it at 8 MB for CSV and TSV, and drops the record the cut left half-read, wherever it fell, quoted fields included; if no complete row is left it says so. Real chunked reads need Range or streaming support on Ganymede's `/files`. The in-browser backend has only the contents API, which sends the whole file; it is read as stored (asking JupyterLite for base64 runs `btoa` over text and garbles accents), which `data-read.test.ts` checks against the real `BrowserStorageDrive`.
- Text is UTF-8, or UTF-16 with a byte order mark; other encodings show replacement characters.
- An open data file has no notebook controller: the sidebar's rename and delete go straight to the contents API and the page follows or closes (`file-actions.ts`), and `PageState.hasNotebook` is false for a data path so the notebook menus disable and the window subtitle shows no kernel. The Mac and iPad rename route through the page only for a notebook. Recents skip data files in `addRecent`.
- Parquet runs through the duckdb-wasm module the page already serves for the browser kernel and the wasm and worker `duckdb-files.ts` caches, in a worker of its own started on the first Parquet file and ended with the view. Columns with no plain JavaScript value (decimals, wide integers, dates, lists) are cast in SQL. `parquet.test.ts` runs the real package's Node build.
- Lumino refuses to detach a widget whose node React already removed, so the widget is made and disposed in a layout effect.
- Not done: real chunked reads (above), Finder opens of data files (the app claims only `.ipynb`), data files in Recents, editing in the table, and drag and drop of data files into the window.
