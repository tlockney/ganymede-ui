## 2026-11-11, cache the XCFramework for a pinned commit (#486)

Between releases `GANYMEDE_REF` has always been a ganymede commit, not a
tag, so the release asset download (#359) never applied and every
`macos-app` run rebuilt GanymedeFFI.xcframework from source: 6 to 12
minutes of bootstrap per run, the same output each time. The job now
caches the built XCFramework under the SHA and `bootstrap.sh` copies it
(`GANYMEDE_XCFRAMEWORK`). The key needs no hash of ganymede's build
script: the SHA fixes the source, and a change to the script here changes
nothing in ganymede's output.

GitHub scopes caches by branch: a pull request reads main's cache and
writes its own, which nothing else reads. So the pin PR builds it, main's
push run builds and saves it once, and later PRs restore it. release.yml
still builds from source; its `macos` and `ios` jobs can restore the same
cache once no release is in flight.
