## 2026-11-09, JupyterLab 4.6.6 packages (#455)

Item 9 of the project read of 2026-11-09 (tlockney/ganymede#629). The app's `@jupyterlab/*` packages were JupyterLab 4.6.4's. They move to 4.6.6, the release Ganymede's `ganymede lab install` pin moves to in tlockney/ganymede#638, so the two repos name one JupyterLab.

- All 22 `@jupyterlab/*` dependencies and the three overrides move to their 4.6.6 releases (4.6.6, or 4.7.6, 6.6.6, 5.6.6, 3.14.6 and 7.6.6 for the packages on their own numbering).
- `@jupyter/web-components` moves to 0.17.1, because `@jupyterlab/ui-components` has depended on `^0.17.1` since 4.6.5. Dependabot still ignores it: it has to move with JupyterLab.
- 0.17.1 is why the tests failed on 2026-11-01. Its `package.json` says `"type": "module"`, so Vitest hands it to Node, and its files import each other without extensions (`./icon.styles`), which Node refuses. 0.16.7 had no `type`, so Vitest saw ES syntax in a CommonJS package and ran it through Vite itself. `server.deps.inline` in `vitest.config.ts` makes Vitest do that for this package again. The build never had the problem: Vite bundles it.
- The lockfile changes only what 4.6.6 requires: the `@jupyterlab/*` packages, `@jupyter/web-components` and `@jupyter/react-components` 0.17.1, and `@codemirror/view` 6.43.15 (`@jupyterlab/codemirror` asks for `^6.43.15`). `npm install` also wanted to move 35 packages nobody asked it to, the d3 family, `es-toolkit` and `vscode-languageserver-protocol`, to releases a few days old. Those entries were put back from `main`'s lockfile; `npm ci` accepts the result and `npm install --package-lock-only` leaves it as it is. Dependabot's weekly run can propose them on their own.
