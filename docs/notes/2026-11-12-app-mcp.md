## 2026-11-12, MCP from the Mac app (#304)

Settings › General › MCP turns on `/mcp` on the app's in-process server:
Off (default), Read only, Edit don't run, Edit and run, and whether
images go to the model. These are ganymede.toml's `mcp_enabled`,
`mcp_read_only`, `mcp_no_execute` and `mcp_images`, passed through the
FFI's config as before; no FFI change.

Discovery: of the three ways #304 listed, Settings shows a config to
copy. Claude Code gets `claude mcp add --transport http` with the
token in an `Authorization` header; Claude Desktop gets an `mcpServers`
entry running `ganymede mcp --server … --token …`, which forwards stdio
to the app, so one server holds each notebook's room. For the config to
outlast a restart, the server's token is, while MCP is on, one the app
keeps in the keychain (`mcp.token`); the port was already kept across
launches. Not chosen:

- Writing `jpserver-<pid>.json` would let `ganymede mcp` find the app
  with no config, but needs a ganymede change, helps only clients that
  have the CLI, and the Mac server is rooted at `/`, which `find_server`
  matches for every notebook folder, so a CLI started anywhere would
  pick the app.
- A fixed-port setting adds a setting the kept port mostly makes
  unneeded.

A change restarts the server, as moving kernels to a remote does, so
turning MCP off ends agents' sessions; kernels restart with it. Toggling
`/mcp` on a running server would need a ganymede API.

Network surface: loopback only (the app's server binds 127.0.0.1), token
required; `/mcp` isn't routed while off.
