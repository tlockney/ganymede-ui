## 2026-10-20, saving: autosave, conflicts, errors (#56)

Also #57, #58 and #59: they share the save path in `NotebookPane`.

Saving moved out of `NotebookPane` into `NotebookSaver` (`src/lib/saver.ts`)
so its races can be unit-tested with JupyterLab's real `NotebookModel`
and a fake contents manager.

- **Serialized saves (#59).** Saves chain on one promise. A save that had
  to wait skips the write if the one before it left the model clean, so
  two ⌘S presses make one PUT. A counter bumped on `contentChanged` is read
  after `beforeSave` (widget state, which itself changes metadata) and
  again after the PUT; dirty is cleared only if it didn't move.
- **Conflicts (#57).** Before writing, a `GET` with `content: false`
  compares `last_modified` with the copy's (from the load, then from each
  save response), with Ganymede's and JupyterLab's 500 ms window. The PUT
  also carries `last_modified`: Ganymede (since 0.2.0) checks it under its
  per-path save lock and answers 409, which closes the gap between the GET
  and the PUT. jupyter_server ignores the field, and JupyterLite's drive
  overwrites it with the save time. A deleted or unreachable file skips
  the check; the save then recreates it or fails on its own.
- **Prompt vs. autosave.** A manual save asks (`window.confirm`) and
  overwrites on yes. Autosave never prompts: a conflict shows a notice and
  turns autosave off until a manual save succeeds, so it doesn't re-check
  every two minutes.
- **Autosave and close (#56).** Every 120 s (JupyterLab's default) and on
  `visibilitychange` to hidden, which is the last event an installed web
  app or a suspended WKWebView reliably gets. `beforeunload` calls
  `preventDefault` and sets `returnValue` while dirty; WKWebView ignores
  it, so the Apple apps rely on the hidden-page save.
  Opening another file saves the dirty one before the pane tears it down
  (the teardown waits for the save, since widget state and the model are
  disposed in it); a failure there can only go to the console.
- **Errors (#58).** Controller actions catch their own rejections and set
  a dismissable notice in the pane, so the toolbar's `void c.save()` and
  ⌘S need no change.

Playwright gets the `beforeunload` dialog from
`page.close({ runBeforeUnload: true })`, but Chromium shows it only after
a user gesture on the page; typing in the cell counts. To fake another
writer in e2e, write the file and push its mtime a few seconds ahead with
`utimesSync`, or it can fall inside the 500 ms window.
