## 2026-11-14, the app's MCP token opens only /mcp (#583)

The Mac app passed its keychain MCP token as the server's `token`, so the
token Settings shows for HTTP agents opened every REST and websocket
route, whatever the MCP mode: a Read only agent could still write files,
start kernels and change grants over REST. ganymede#781 (#766) added
`mcp_token`, which `/mcp` accepts and no other route does.

`AppMCP.serverConfig` now passes the keychain token as `mcp_token` and
leaves `token` unset, so the server makes its own random token per launch,
which the page gets through the server's URL. The server info file that
`ganymede mcp` reads holds that server token, as `ganymede serve` writes
it, taken from the URL rather than the settings. Off and Reset Token
revoke the keychain token as before.

That confines an HTTP agent only while it can't run code: a cell can read
the server token from the server info file, and an agent reads any output
that shows it. An agent using `ganymede mcp` gets the server token from
that file, as with `ganymede serve`. `GANYMEDE_REF` moves to ganymede's
main at #781, so the XCFramework is built from source until the next
ganymede release.
