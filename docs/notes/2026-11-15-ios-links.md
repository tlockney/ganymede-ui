## 2026-11-15, ganymede:// links on iPad and iPhone (#640)

The iPad and iPhone app opens `ganymede://open` links, for the Obsidian
plugin (obsidian-notebooks) and anything else that can open a URL. It
reads only in the folder the app has open and in folders the person
granted in Settings › Link Folders or from the alert a refused link shows
(security-scoped bookmarks, `LinkFolderStore`). `AppURL` takes
`open?folder=<name>&file=<relative path>` beside `path=`; `LinkFolders`
resolves either form against those folders as a pure function: it
standardizes, follows symlinks, and requires the result inside one folder
(the most specific, or the one the name picks), so `..` and a symlink
that leaves the folder are refused, and a name two folders share is an
error that suggests `path=`, opening another folder, or revoking one
(the open folder is always a candidate, so revoking doesn't always help).
The Mac handler refuses `folder=` links with a message. The refusal
doesn't depend on whether the file exists, so a web page learns nothing
about files outside the grants; the iCloud check, which does look at the
file, runs only after a folder holds it.

`LinkOpener` holds the decisions and takes the open folder, the open
text files and the actions as arguments (and iCloud hooks and a scheduler
for notices), so it is tested without the app (`LinkOpenerTests`). The
iOS-only parts are in `LinkOpener.swift` under `#if os(iOS)`: `LinkAlert`,
the modifier that shows its notice; `FolderPick`, what the folder picker
is for; and `LinkFoldersSettings`, Settings › Link Folders (named so it
doesn't clash with the Mac's Settings › General › Links); the rest is in
`ContentView` (`onOpenURL`, the pickers, the sheet and covers) and
`SettingsScreen`. A link opens in the root without resolving any
bookmark when the open folder holds the file; only a folder name a
granted folder also has goes the long way, to tell whether it is
ambiguous. A notebook in a granted folder other than the open one asks
first, since opening it restarts the server and stops its kernels. It is
refused while a text file is open (the iPhone editor, the iPad's stack):
the editor would save into the new folder. The notebook's path in the
folder is worked out inside the folder's access, and opens when the page
is ready again on the new folder, not at once, because the old page
stays ready until the new one commits. An alert's own action may post
another notice (a folder revoked since the question), and a notice posted
as a picker or alert closes can be dropped, so those are posted through a
scheduler (`ContentView.afterPresentationEnds`, 0.3 s; tests run them at
once); closing an alert clears only the notice it showed. A `folder=` link
whose file leaves the folder is `badPath`, not `notGranted`, so it has no
Grant Access… button.

A link closes nothing. It may come from any web page, and a terminal, an
SSH session or an edit in Settings would be lost. `LinkAlert` and a link
folder picker are attached to the window, the Settings sheet, and the
terminal and editor covers, and only the topmost presented one is
enabled, so the alert shows once, over what is up. On the iPhone an
in-root link always pushes the notebook, behind any cover. A link opens
in the window showing it (`handlesExternalEvents(preferring:allowing:)`
on the main view; Terminal and Editor scenes don't have it).

Paths are compared by `AppURL.resolvedURL`, which resolves the deepest
part that exists, follows a dangling symlink to where it points, and
appends the rest. Foundation's `resolvingSymlinksInPath` drops `/private`
only from a path that exists and leaves a missing last component alone, so
a missing or evicted file would not have matched its own folder (and a
symlinked folder that leaves the vault, with a missing file under it, would
have passed). `LinkFolders.resolve` resolves each folder and the file once
and compares strings. An iCloud Drive file that isn't on the device (a
hidden `.name.icloud` placeholder iCloud manages, as DeviceBridge's
`Folders.placeholder(for:)` asks) starts downloading and the link says to
try again; files iOS evicts without a placeholder aren't detected. The
Settings importer and the link picker share `LinkFolderStore.add(picked:)`.
`run` and `new` are Mac only, and x-callback answers are never opened on
iOS.

The Obsidian plugin's "Open in Ganymede" on iPad and iPhone isn't done
here: it is deferred to obsidian-notebook-library#8.

None of the Swift was built or run in the container; CI is its first
compile. Not checked: the folder picker after the "Grant Access…" alert,
which waits 0.3 s because SwiftUI has no signal for the alert's dismissal
finishing, and a real Obsidian vault on an iPad.
