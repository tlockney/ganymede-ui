## 2026-11-15, ganymede:// links on iPad and iPhone (#640)

The iPad and iPhone app opens `ganymede://open` links, for the Obsidian
plugin (obsidian-notebooks) and anything else that can open a URL. It
reads only in the folder the app has open and in folders the person
granted in Settings › Links or from the alert a refused link shows
(security-scoped bookmarks, `LinkFolderStore`). `AppURL` takes
`open?folder=<name>&file=<relative path>` beside `path=`; `LinkFolders`
resolves either form against those folders as a pure function: it
standardizes, follows symlinks, and requires the result inside one folder
(the most specific, or the one the name picks), so `..` and a symlink
that leaves the folder are refused, and a name two folders share is an
error that suggests `path=`, opening another folder, or revoking one
(the open folder is always a candidate, so revoking doesn't always help).
The Mac handler refuses `folder=` links with a message. The refusal
doesn't depend on whether the file exists, so a web page learns nothing
about files outside the grants; the iCloud check, which does look at the
file, runs only after a folder holds it.

`LinkOpener` holds the decisions and takes the open folder and the
actions as arguments (and an iCloud download hook), so it is tested
without the app (`LinkOpenerTests`). The iOS-only parts are in
`LinkOpener.swift` under `#if os(iOS)`: `LinkAlert`, the modifier that
shows its notice; `FolderPick`, what the folder picker is for; and
`LinkFoldersSettings`, Settings › Links; the rest is in `ContentView`
(`onOpenURL`, the picker, the covers) and `SettingsScreen`. A notebook in a
granted folder other than the open one asks first, since opening it
restarts the server and stops its kernels; it opens when the page is
ready again on the new folder, not at once, because the old page stays
ready until the new one commits. An alert's own action may post another
notice (a folder revoked since the question), so closing an alert clears
only the notice it showed.

Paths are compared by `AppURL.resolvedURL`, which resolves the deepest
part that exists and appends the rest. Foundation's
`resolvingSymlinksInPath` drops `/private` only from a path that exists
and leaves a missing last component alone, so a missing or evicted file
would not have matched its own folder (and a symlinked folder that leaves
the vault, with a missing file under it, would have passed). A link
arriving over Settings closes it, and over a terminal on the iPhone closes
that; the link waits 0.3 s for them to go. It doesn't close a text file
being edited, which may have unsaved edits: `LinkAlert` is attached to
the window and to the editor's cover, enabled for one at a time, and the
folder picker has one in each too. A link opens in the window showing it
(`handlesExternalEvents(preferring:allowing:)` on the main view; Terminal
and Editor scenes don't have it). An iCloud Drive file that isn't on the
device (a hidden `.name.icloud` placeholder is there) starts downloading
and the link says to try again; files iOS evicts without a placeholder
aren't detected. `run` and `new` are Mac only, and x-callback answers are
never opened on iOS.

None of the Swift was built or run in the container; CI is its first
compile. Not checked: the folder picker after the "Grant Access…" alert,
which waits 0.3 s because SwiftUI has no signal for the alert's dismissal
finishing, and a real Obsidian vault on an iPad.
