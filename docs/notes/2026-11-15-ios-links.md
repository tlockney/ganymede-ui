## 2026-11-15, ganymede:// links on iPad and iPhone (#640)

The iPad and iPhone app opens `ganymede://open` links, for the Obsidian
plugin (obsidian-notebooks) and anything else that can open a URL. It
reads only in the folder the app has open and in folders the person
granted in Settings › Links or from the alert a refused link shows
(security-scoped bookmarks, `LinkFolderStore`). `AppURL` takes
`open?folder=<name>&file=<relative path>` beside `path=`; `LinkFolders`
resolves either form against those folders as a pure function: it
standardizes, follows symlinks, and requires the result inside one folder
(the most specific, or the one the name picks), so `..` and a symlink
that leaves the folder are refused, and a name two granted folders share
is an error. The Mac handler refuses `folder=` links with a message. The
refusal doesn't depend on whether the file exists, so a web page learns
nothing about files outside the grants. A notebook in a granted folder
other than the open one asks first, since opening it restarts the
server and stops its kernels; the notebook opens when the page is ready
again on the new folder, not at once, because the old page stays ready
until the new one commits. `run` and `new` are Mac only, and x-callback
answers are never opened on iOS. None of the Swift was built or run in
the container; CI is its first compile. Not checked: the folder picker
after the "Grant Access…" alert (shown 0.3 s later, in case a sheet
shown during an alert's dismissal is dropped), an iCloud Drive folder
whose files aren't downloaded (they may read as not found), and a real
Obsidian vault on an iPad. The by-hand check goes in #273.
