## 2026-11-20, DuckDB console names and recent consoles (#735)

There was no way back to a console after leaving it, which hurt most after Export to Notebook (which closes the page's console, or leaves a tab to close by hand). Each console now has a name and a record of what ran, and recent consoles open again.

Design:

- **The record's id is the Mac tab's id.** `WindowTarget.console(folder:id:)` already had a UUID per tab. `pageURL` now writes it as `session=` (lower case), `init?(page:)` reads it back (new UUID without one), and the page (`readLaunch`, `Launch.session`) uses it as the console's record id. So a restored tab (SceneStorage keeps the target) is the same record, a recent console opens as `TabRequest.duckdbConsole(folder:session:)` (also the `openTab` message's new optional `session`), and no field was added to `WindowTarget`: an old saved console target decodes as before, and its page gets a `session` from its id. Reopening a console that has a tab comes forward because SwiftUI's `openWindow(value:)` matches the equal value (same folder and id); if the folder was renamed since the tab's target was made, the values differ and a second tab opens, both on the one record. The tab target's folder isn't updated by a move (nor was it before).
- **Storage** (`src/lib/console-recents.ts`): `ganymede-ui:console-recents`, `{ [recentsKey]: ConsoleRecord[] }`, 20 per server, 200 statements each (oldest dropped), 10 servers, most recently saved first, malformed records dropped on read, every write in a try/catch. `useConsoles` follows changes here and in other tabs. A record is made by the first statement that runs (or a rename); a console that ran nothing leaves none. So two consoles opened before either ran anything both get "Console 1": the number is the lowest unused among _records_.
- **Who owns what.** `App` owns the shown console's `{ id, name }` (`duck`), because File > Rename… and the palette act through the `rename` command; `DuckdbConsole` gets `name`, `onRename` and `onOpenConsole` and writes the record after each statement (`remember`: restored statements, then those run since). `rename` renames the console while one shows, before the notebook case. `PageState` gained `console: { id, name } | null` and `consoles: [{ id, name, folder }]` (the latter only with `chrome=native`); Swift reads both as optional, so older pages decode.
- **Folder moves.** `followFolder` (the sidebar's renames and the app's `file-moved`) calls `moveConsoleFolders`, which moves the records in the folder as it moves the shown console, and drops them when the folder is deleted (nothing to read from).
- **Restored statements** show as entries in a `restored` state ("Not run in this session") with no results, and fill the ↑ history. **Run All Again** runs the restored ones as one `runInput` turn: an error stops it and leaves the rest restored. It adds nothing to the record (they are in it); a statement run before it is appended in order. Dot commands are kept too, as the scrollback has them.
- **Opening** goes through the `open-console` command (id as argument), used by the palette, the console's Recent menu and the Mac's menu (which opens the window itself from `PageState.consoles` rather than through the page). With `openTab` it asks the app for a tab; without one it replaces the page's console (a new engine) unless that console is the one shown.
- **Swift.** `PageState.Console`/`RecentConsole`, `canRename`; `WindowTarget.tabTitle(consoleName:)` for the tab's title; `RenameCommand` (enabled for a console); an Open Recent Console submenu in `OpenCommands`.

Tests: `console-recents.test.ts` (cap, order, per server, corrupted and failing storage, numbering, folder moves), `DuckdbConsole.test.tsx` (rename keys, records, reopen and Run All Again, error stop, Recent menu, storage failure), `App.test.tsx` (session, default name, restored record, rename command, `open-console` as a tab and in the page, `file-moved`), `palette.test.ts`, `launch.test.ts`, and Swift `WindowTargetTests` (session in the page URL and back, an old saved console target, tab title, the message's session) and `PageStateTests`. Swift isn't compiled in the container.

Not done: the page's `document.title` for a console, a name shown in the Mac's Window menu beyond the tab title, results kept between sessions, a limit on one statement's size.

By hand (Mac, a build of `main`):

1. New DuckDB Console, run `select 1;`; File > Rename… names it and the tab title follows; click the name in the header, type, Enter; Esc cancels.
2. New DuckDB Console again: "Console 1" is taken, so this is "Console 2" once it has run a statement. File > Open Recent Console lists both with their folders.
3. Open the first from the menu: its tab comes forward. Close it, open it again from the menu: a tab with the name and the statement, "Not run in this session"; Run All Again runs it; a new statement adds to it; the Recent menu in the header and the palette list the others.
4. Quit and relaunch: the console tab comes back with the name and statements.
5. Rename the console's folder in the sidebar; the recent console's folder follows. Clear Recent Consoles empties the menu.
