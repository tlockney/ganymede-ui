## 2026-10-19, user docs: modes, deploying, shortcuts, data, known gaps (#75)

From the docs review (#75, #76, #77, #80, #81, #82, #83, #89). The README

with where notebooks and kernels live in each mode (the backends diagram

then Run with its prerequisites, Using it, Where your data lives, and a
current Known gaps list that links the open issues. The contributor
rundown (checks, e2e, releases, icons) and what's next moved to
[CONTRIBUTING.md](../../CONTRIBUTING.md); Findings shrank to a Background
paragraph. The stale "Not working" list in [archive.md](archive.md) now
says it is historical.

Two new pages render on the Ganymede site with the rest of `docs/`:
[deploying.md](../deploying.md), with copy-paste setups for the app served
by Ganymede and on another origin, and [shortcuts.md](../shortcuts.md).
The shortcuts tables come from `SHORTCUTS` in `src/lib/shortcuts.ts`: a
Vitest test (`src/lib/shortcuts-doc.test.ts`) fails when they differ and
rewrites them with `UPDATE_DOCS=1`. It compares with whitespace collapsed,
since Prettier pads table cells.

`package.json` now has `engines.node: ">=22.12"`, Vite 7's floor on the
22 line; CI stays on 24.

Trying the cross-origin steps against Ganymede 0.3.0 found a bug (#92):
the app sent `credentials: 'include'` to any server URL, and Ganymede's
CORS answers without `Access-Control-Allow-Credentials`, so the browser
blocked every request. The token authenticates, so the app now sends
cookies across origins only when it has no token. Checked with the
preview build on :4173 connecting to `ganymede serve --allow-origin
http://localhost:4173` on :8888: notebook list, kernel start, Run All.
