## Facts you need

- `Place` (`apple/Sources/Ganymede/Place.swift`): `.thisDevice` or
  `.machine(id)`; a machine's id is its `Remote.id.uuidString`
  (`Remote.sharesName(for:in:)` in `Remote.swift` shows the lookup).
  `Capability.localTerminal` = a shell on this device; keep it
  this-device only and keep its meaning.
- `TerminalTarget` (`Terminal/TerminalTarget.swift`): `.local(folder:)`,
  `.server(UUID)`, `.ssh(UUID)`. It is Codable and saved with restored
  windows and panels, so old JSON must still decode.
- `TerminalWindow.swift`: `makeTransport()` builds
  `JupyterTerminalTransport(endpoint:cwd:)`; `.server` passes no cwd
  today. `problem` and `model.title(for:)` ("Terminal on <remote>").
  `TerminalCommands` (Mac File menu) disables New Terminal / New
  Terminal Tab when `scope?.place.allows(.localTerminal)` is false.
- The Ganymede server resolves a relative terminal `cwd` against its
  root and falls back to the root when it doesn't exist
  (ganymede `crates/ganymede-terminals` `resolve_cwd`), so a
  machine-relative folder is a valid cwd.
- `ContentView.swift`: `WindowSceneValues` publishes `windowFolder` and
  `panelController` only for this device's windows; `WindowScope`
  (`FocusedModels.swift`) has `place` and `serverFolder`. iOS:
  `appButtons` (TerminalMenu, panel toggle), `panelShown`,
  `togglePanel`; `IPadChrome.swift` `runningCount` and the Running
  tab's `IPadPanelTerminalRows`. `BottomPanel.swift` and
  `NativeChrome.swift` also add terminals.

## Changes

1. `TerminalTarget.server` gains an optional start folder:
   `case server(UUID, folder: String? = nil)`. Synthesized Codable
   decodes a missing optional as nil; add a test that JSON saved by the
   old shape (encode an old-shaped value by hand, e.g.
   `{"server":{"_0":"<uuid>"}}`) decodes to `.server(id, folder: nil)`.
   Update every `case .server(let id)` pattern. `makeTransport()` passes
   `folder` as `cwd`.
2. One tested function decides the target, e.g. in `Place.swift`:
   `func terminalTarget(folder: ..., remotes: [Remote]) -> TerminalTarget?`
   - this device: `.local(folder:)` (as today);
   - a machine whose remote exists and `hasServer`:
     `.server(remote.id, folder: <machine-relative folder or nil>)`;
   - otherwise nil (removed machine, no server, invalid id).
3. Mac: `TerminalCommands` uses that function. New Terminal and New
   Terminal Tab are enabled whenever it returns a target. In a machine's
   window the terminal goes to that window's bottom panel; publish
   `panelController` for machine windows too if that is what it takes,
   but not `windowFolder` (that is this Mac's disk). Start folder: the
   folder of the window's open notebook when the window knows it (look
   at what `WindowScope.serverFolder` holds for a machine and at the page
   state's `path`), else nil (the machine's root).
4. iOS: a machine's scene shows the terminal menu, the bottom panel and
   its toggle, and the Running tab's panel terminals; new terminals use
   the same function. Replace the `place.allows(.localTerminal)` checks
   that are about "this window has terminals" with a check on the
   target (keep `localTerminal` where it really means a shell on this
   device). Update comments that say a machine has no terminals.
5. Tests (`apple/Tests/GanymedeTests`): the target function (this
   device, machine with server, machine with no server, removed
   machine, folder passed through), the Codable compatibility test, and
   PlaceTests if the table changes. Each must fail without the change.
6. docs/apps.md: where it says a machine's window has no terminals,
   say they open on the machine, under the section's existing
   `> [!NOTE] **Unreleased.**` note (extend it) or a new one.
7. Dev log `docs/notes/2026-11-26-machine-terminals.md`, starting
